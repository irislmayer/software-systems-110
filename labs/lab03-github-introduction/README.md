# What is GitHub?
GitHub **stores** and **manages** code projects

## Well then what even is "git"?
*Git* is a *version control system* that tracks code changes and authors

### I'm confused. I'm looking at someone's "repository" in GitHub but there seems to be a million versions of the same thing.  What is all this? Fork, clones, branch - don't they all mean the same thing?
Let's break it down.
 - **Repository**: This is the project folder stored in GitHub. It is where the code actually lives.
 - **Fork**: This is *your* copy of someone's repository. You can experiment in it without affecting that original project stored in the repository.
 - **Clone**: This is the act itself of copying a remote repository to your device. It creates a local version of the big project, so you can use it in your chosen Integrated Development Environment.
 - **Branch**: This is a separate version of the project you work on in your IDE. Great for testing, you can make changes without potentially messing anything up in the main project.

So now that you're looking at someone's **repository**, you could create a **fork** on your GitHub page, open up the IDE of your choosing, **clone** that fork and then start working on your own **branch** of the project, all without ever affecting that repository you're looking at now.


---
### Ok, great. I have made some changes. Now what? They stay on my device, local forever? 
No, now you can send thoses changes to your fork on GitHub, following these steps.
 1. **Stage**: This selects which changes to save. use command "*git add .*" to send all changes you made.
 2. **Commit**: This actually saves what you just staged. Include a comment describing what you changed, using command "*git commit -m 'changes made'*"
 3. **Push**: This presses the button to finally send your changes to the remote repo you choose. Use the command "*git push origin 'branchname'*" to send the changes back to the fork you originally cloned this code from.
  
  **Note**: The command "*git pull origin 'branchname'*" essentially works in reverse from **push**, pulling the latest changes from your specified origin. This is a good idea to always do before starting work in case others on your project have made recent changes.
